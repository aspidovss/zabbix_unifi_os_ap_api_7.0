# Wi-Fi клиенты по фильтру — дополнительный шаблон

[English](WIFI_CLIENTS.md) | **Русский** · [Основной README](../README.ru.md)

Дополнение к шаблонам UniFi Network API. Оно создаёт **отдельный хост Zabbix для каждого клиента UniFi, который подходит под ваш фильтр**: имя Wi-Fi сети, имя клиента, производитель MAC или их сочетание. На каждом хосте клиента — сигнал, скорости, повторы, CCQ, Experience, журнал роуминга, ICMP ping и аномалии UniFi.

Для чего: сканеры штрихкодов, платёжные терминалы, IoT-контроллеры, PTP-мосты, камеры — любые **стационарные устройства с постоянным MAC-адресом**, за которыми нужно следить поштучно.

- **Файл:** `template/zbx_unifi_wifi_clients_7.0.yaml`
- **Zabbix:** 7.0
- **Работает с основным шаблоном** `zbx_unifi_network_api_7.0.yaml` **и без него**: нужны только те же два глобальных макроса.
- **Лицензия:** MIT · **Автор:** AspidovSS

## Как это работает

```
Хост «UniFi Clients: Scanners»          создаёте вы, шаблон «… - Wi-Fi Clients Filter»
  {$FILTER.SSID} = ^scanners$           ваш фильтр
  │
  └─ Discovery Filtered Clients          (все сайты, раз в 30 мин)
       └─ UniFi [<сайт>] - <категория>:<имя>     шаблон «… - Wi-Fi Client»
```

- **Один фильтр — один хост.** Для нескольких категорий устройств создайте несколько хостов-фильтров, у каждого свои макросы.
- **Хост-фильтр читает все сайты** контроллера раз в 30 минут (`stat/sta`, один запрос на сайт) и оставляет подходящих клиентов.
- **Должны совпасть все заполненные фильтры** (логическое И). Пустые фильтры не используются. Хотя бы один из `{$FILTER.SSID}`, `{$FILTER.NAME}`, `{$FILTER.OUI}` должен быть задан.
- **Безопасное обнаружение.** Если какой-то сайт не ответил, проход пропускается, и клиенты этого сайта не помечаются как потерянные.
- **Предохранитель.** Если под фильтр попало больше `{$FILTER.MAX_CLIENTS}` (200) клиентов, обнаружение не выполняется, а хост-фильтр показывает ошибку. Это защищает Zabbix от слишком широкого фильтра, например гостевой сети с сотнями телефонов.

## Установка

1. **Глобальные макросы.** Создайте `{$UNIFI_NETWORK_API_ADDRESS}` и `{$UNIFI_NETWORK_API_KEY}`, как описано в [основном README](../README.ru.md#установка). Если основной шаблон уже работает, они уже есть.
   Необязательно: создайте группу хостов **`UniFi Network`**, тогда `UniFi Network/Wi-Fi Clients/...` будут показаны как её подгруппы.
2. **Импортируйте** `template/zbx_unifi_wifi_clients_7.0.yaml` (*Сбор данных → Шаблоны → Импорт*).
3. **Создайте хост-фильтр.** Имя любое, например `UniFi Clients: Scanners`. Интерфейс не нужен. Привяжите шаблон **UniFi Network API - Wi-Fi Clients Filter**.
4. **Задайте фильтр** на вкладке *Макросы* этого хоста:
   - хотя бы один из `{$FILTER.SSID}`, `{$FILTER.NAME}`, `{$FILTER.OUI}`;
   - `{$FILTER.CATEGORY}`: название категории устройств, например `Scanner` (у каждого хоста-фильтра своё);
   - `{$FILTER.PREFIX}`: короткий уникальный префикс из латиницы, цифр, `.`, `_`, `-`, например `scanner`.
5. **Проверьте фильтр.** У элемента **Filtered Clients JSON (all sites)** нажмите **Test** → **Get value and test**. Вы увидите список подходящих клиентов.
6. **Запустите обнаружение:** **Execute now** у **Filtered Clients JSON (all sites)**. Хосты клиентов появятся в течение минуты.

## Макросы фильтра

| Макрос | С чем сравнивается | Пример |
|---|---|---|
| `{$FILTER.SSID}` | имя Wi-Fi сети | `^scanners$`, `^(iot\|sensors)$` |
| `{$FILTER.NAME}` | имя клиента в UniFi **или** его hostname | `^wirenboard`, `^TSD-` |
| `{$FILTER.OUI}` | производитель MAC, как его показывает UniFi | `ubiquiti`, `zebra\|honeywell` |
| `{$FILTER.SITE}` | имя сайта (пусто = все сайты) | `^Тюмень$` |
| `{$FILTER.EXCLUDE}` | пропускать клиентов, у которых имя, hostname или MAC совпадает | `test\|spare` |
| `{$FILTER.WIRED}` | `1` = также проводные клиенты (только без фильтра по сети) | `1` |
| `{$FILTER.RANDOM_MAC}` | `1` = также случайные (приватные) MAC-адреса | `0` |

Все регулярные выражения без учёта регистра. В макрос Zabbix регулярное выражение пишется как есть, без слэшей.

## Примеры

| Задача | Макросы хоста-фильтра |
|---|---|
| Все клиенты сети `scanners` | `{$FILTER.SSID}` = `^scanners$`, `{$FILTER.CATEGORY}` = `Scanner`, `{$FILTER.PREFIX}` = `scanner` |
| Только устройства Zebra в этой сети | добавить `{$FILTER.OUI}` = `zebra` |
| Контроллеры Wiren Board, проводные и беспроводные | `{$FILTER.NAME}` = `^wirenboard`, `{$FILTER.WIRED}` = `1`, `{$FILTER.CATEGORY}` = `Wirenboard`, `{$FILTER.PREFIX}` = `wb` |
| PTP-мосты Ubiquiti (например, airMAX Loco M2) | `{$FILTER.OUI}` = `ubiquiti`, `{$FILTER.CATEGORY}` = `PTP`, `{$FILTER.PREFIX}` = `ptp` |
| Терминалы одного сайта, без тестовых | `{$FILTER.SSID}` = `^pos$`, `{$FILTER.SITE}` = `^Тюмень$`, `{$FILTER.EXCLUDE}` = `test` |

## Хосты, группы и теги

| | Значение |
|---|---|
| Имя хоста | `UniFi [<сайт>] - <категория>:<имя>` |
| Техническое имя хоста | `<префикс>-<mac без двоеточий>` |
| Группы хостов | `UniFi Network/Wi-Fi Clients` и `UniFi Network/Wi-Fi Clients/<категория>` |
| Теги хоста | `UniFi` = `<категория>`, `UniFi Site` = имя сайта |
| Интерфейс | IP клиента из UniFi (для ICMP ping) |

- **`<имя>`** — имя клиента в UniFi, если его нет — hostname, если нет и его — MAC. Если у двух клиентов одного сайта одинаковое имя, к нему добавляется MAC: `Scanner (24:5a:4c:11:22:33)`. Давайте устройствам понятные имена в UniFi, тогда и имена хостов в Zabbix будут понятными.
- **`{$FILTER.PREFIX}` и `{$FILTER.CATEGORY}` у каждого хоста-фильтра должны быть свои.** Zabbix требует уникальных технических и видимых имён хостов. Если одно устройство подходит под два фильтра, оно получит два независимых хоста, только если различаются и префикс, и категория.

## Жизненный цикл клиента

| Сколько не в сети (или не подходит под фильтр) | Что происходит |
|---|---|
| любое время | данные не обновляются, хост продолжает работать |
| 48 ч | событие *Client not connected for more than 48h* (Information) |
| 30 дней | хост **отключается** |
| 31 день | хост **удаляется** вместе с историей |

- **Подключился снова в течение 30 дней:** обнаружение найдёт его, и мониторинг продолжится на том же хосте.
- **Перешёл в сеть, которая не входит в фильтр:** для этого фильтра клиент пропал, действуют те же правила.
- После импорта проверьте правило **Discovery Filtered Clients**: «Отключать потерянные ресурсы: через 30d», «Удалять потерянные ресурсы: через 31d».

## Что мониторится

### Хост-фильтр

| Элемент | Значение |
|---|---|
| Filtered Clients Connected | подключённые клиенты, подходящие под фильтр (все сайты) |
| Random MAC Clients Skipped | подходящие клиенты, пропущенные из-за случайного MAC |

### Хост клиента (`UniFi Network API - Wi-Fi Client`)

| Группа | Элементы |
|---|---|
| Подключение | подключён (1/0), точка доступа (записывается **только при смене**: журнал роуминга, 30 дней), MAC точки, SSID, сеть, IP, время подключения, число переключений, первое появление, последнее подключение, hostname, производитель MAC, тип подключения (Wired / Wireless) |
| Сигнал | сигнал, шум, SNR, Tx/Rx Rate, Tx Retries, CCQ, MCS, Tx Dropped %, Experience |
| Радио | диапазон, канал, ширина канала, стандарт Wi-Fi, MIMO |
| Трафик | download / upload (bps), Tx пакеты/с, всего скачано / отправлено |
| Ping | ICMP ping, потери, время ответа |
| Аномалии | счётчик аномалий UniFi, активные аномалии, длительность, минуты за последний час, интервалы за 24 ч |

- **Проводные клиенты.** Радио-элементы остаются пустыми, а не нулевыми, поэтому ложных тревог не дают. Вычисляемый элемент *Tx Dropped* у них показывает *Not supported*, это нормально.
- **Значения, которые UniFi не сообщает** (например CCQ или Experience у некоторых клиентов), не записываются как 0: элемент сохраняет последнее значение, поэтому ложных тревог по низким значениям нет.

## Триггеры

### Хост-фильтр

| Триггер | Уровень | Условие по умолчанию |
|---|---|---|
| Client filter: no data for {$TRIGGER_FILTER_NODATA} | Warning | нет данных 2 ч: ошибка API, нет фильтра, неверное регулярное выражение или превышен лимит |

### Хост клиента

| Триггер | Уровень | Условие по умолчанию |
|---|---|---|
| Client not connected for more than … | Info | клиент не в сети 48 ч |
| Client roamed to AP "…" (событие: `Client roamed: <откуда> -> <куда>`) | Info | смена точки доступа; закрывается через 1 мин |
| Very weak signal … | Average | очень слабый сигнал: < −80 dBm 10 мин |
| Weak signal … | Warning | слабый сигнал: < −75 dBm 10 мин |
| Tx / Rx Rate above … Mbps | Info | **выключен**; скорость > `{$TRIGGER_CLIENT_RATE_HIGH}` Mbps 10 мин |
| Tx / Rx Rate below … Mbps | Warning | **выключен**; скорость < `{$TRIGGER_CLIENT_RATE_LOW}` Mbps 10 мин |
| Tx Retries > …% | Warning | повторы > 30% 30 мин, только при > 5 пакетов/с |
| Low CCQ … | Warning | CCQ < 50% 30 мин, только при > 5 пакетов/с |
| Dropped frames > …% | Warning | потерянные кадры > 5% 30 мин, только при > 5 пакетов/с |
| Low Experience: average below …% | Warning | среднее Experience за 7 дней < 70% |
| UniFi anomaly for … | Warning | активная аномалия UniFi ≥ 30 мин |
| Client is connected in UniFi but does not respond to ping … | Average | подключён, но нет ping 5 мин; выключается `{$TRIGGER_CLIENT_PING}` = `0` |

Имена триггеров даны так, как они видны в Zabbix; `…` — порог или значение.

- **Тревоги по скорости по умолчанию выключены.** Простаивающее устройство часто передаёт на минимальной скорости, поэтому тревога по низкой скорости имеет смысл только для устройств с постоянным трафиком, например PTP-мостов.
- **Где менять пороги.** В макросах шаблона **UniFi Network API - Wi-Fi Client**: они действуют на хосты клиентов всех фильтров. Макросы хоста-фильтра на хосты клиентов **не** передаются (обнаруженные хосты Zabbix их не наследуют).

## Случайные MAC-адреса

Телефоны, планшеты и ноутбуки обычно подключаются со **случайным (приватным) MAC-адресом**. Он свой для каждой сети и может меняться со временем. Каждый новый MAC стал бы новым хостом Zabbix.

- **По умолчанию такие клиенты пропускаются.** Случайный MAC распознаётся по самому адресу (бит «локально администрируемый»). Такие клиенты считаются в **Random MAC Clients Skipped**, но хост не получают.
- **Чтобы включить их,** задайте `{$FILTER.RANDOM_MAC}` = `1`. Делайте это, только если устройства сохраняют свой MAC, например если на них отключены приватные адреса.

## Нагрузка на контроллер

| Источник | Запросов |
|---|---|
| каждый хост-фильтр | (число сайтов + 1) раз в 30 минут |
| каждый хост клиента | ~0.7 в минуту (данные клиента раз в 2 мин + аномалии раз в 5 мин) |

**Пример:** 100 хостов клиентов ≈ 70 запросов в минуту. Каждый запрос клиента читает список клиентов его сайта, поэтому на сайтах с большим числом клиентов увеличьте `{$ITEM_CLIENT.JSON_UPDATE}` в шаблоне **UniFi Network API - Wi-Fi Client**.

ICMP ping идёт от Zabbix напрямую к клиенту и контроллер не нагружает.

## Ограничения

- **Zabbix 7.0.** Используется недокументированный внутренний API UniFi (`stat/sta`, `stat/anomalies`), он может измениться в будущих версиях UniFi.
- **Пороги клиентов общие для всех хостов-фильтров** (макросы шаблона). Отдельные пороги для категории в этой версии не поддерживаются.
- **Устройства за мостом** (например, за Loco M2 в режиме Station, MAC NAT) UniFi не видит, поэтому они не находятся.
- **ICMP ping** требует маршрута от Zabbix-сервера или прокси в сети клиентов и установленного `fping`. Если его нет, выключите тревогу ping: `{$TRIGGER_CLIENT_PING}` = `0`.
- **Название события роуминга** использует макрос-выражение, чтобы показать предыдущую точку. Если там `*UNKNOWN*`, событие всё равно работает.
- **Настройки потерянных ресурсов** (30 / 31 день) записаны полями экспорта Zabbix 7.0 `enabled_lifetime_type` / `lifetime_type`. Проверьте их после импорта.

## Устранение неполадок

| Симптом | Причина / решение |
|---|---|
| `No filter set: …` | задайте на хосте-фильтре хотя бы один из `{$FILTER.SSID}`, `{$FILTER.NAME}`, `{$FILTER.OUI}` |
| `Invalid regular expression in the … filter` | исправьте регулярное выражение в этом макросе |
| `Filter matches N clients, the limit is 200` | сузьте фильтр или увеличьте `{$FILTER.MAX_CLIENTS}`, если так и задумано |
| `stat/sta failed for N of M sites` | API не ответил по этим сайтам; обнаружение намеренно пропускает проход |
| Клиент не появился | нажмите **Test** у элемента фильтра; проверьте имя / SSID / производителя клиента в UniFi; посмотрите *Random MAC Clients Skipped* |
| `Host with the same name … already exists` / `… same visible name …` | устройство уже есть как хост другого фильтра или шаблона: задайте другие `{$FILTER.PREFIX}` и `{$FILTER.CATEGORY}` |
| `The prefix filter macro may contain only …` | в `{$FILTER.PREFIX}` используйте только латиницу, цифры, `.`, `_`, `-` |
| ICMP Ping всегда 0 | нет маршрута от Zabbix в сеть клиентов или не установлен `fping` |
